## What to build

[ADR 0013](../../docs/adr/0013-hosted-taus-handles-and-public-pages.md) §4. Each hosted tau gets keys in its `Tau` object (sealed by the vault), a card at `/@<handle>/.well-known/tau.json` and an inbox at `/@<handle>/net/inbox` with the spine's checks and limits. Delivered envelopes are opened in the `Tau` object and handled like tau-net: contacts state machine with key pinning, network turns (persona + public note, no profile, no tools, no approvals, hops and hourly caps, `[no reply]`), public sub-tau routing via `sub`. The app gets contacts (add by address, accept, block), a network log, and `net_send` as a tier-2 tool with an approval card. Universe join/report/leave signed with the tau's key (toggle in the app; the sign-up asks explicitly, nothing preselected).

## Acceptance criteria

- [x] A hosted tau and a local hub (two-process test or recorded vectors) exchange a contact request, accept and messages both ways
- [x] A hosted tau's public sub-tau answers `<host>/@h/coach` from a hub; a private one is dropped
- [x] Universe join/report from the app; the snapshot lists the hosted tau with its handle

- 2026-09-30: done. As built:
  - **Address:** `<net host>/@<handle>`; the net host is `PUBLIC_HOST` when set (tau.getporti.com), else the request host, which the `Tau` object remembers (`net_host`) for its alarm work. No new variable: set `PUBLIC_HOST` before taus join, another host is another address. An invalid host (e.g. `[::1]`) answers the card and inbox with 503 `not_configured`.
  - **Identity:** made on first need (card, inbox, send) with `Identity.generate()`, sealed as `seal(VAULT_KEY, handle, "net_key", identity JSON)` in `settings.net_identity`; never returned, exported or logged.
  - **Routes** (src/router.ts, src/net/routes.ts): `GET /@<handle>/.well-known/tau.json` (CORS `*`, `public, max-age=300`; name = the owner's `net_name` or `@<handle>`, `software` `tau-host/0.1.0`), `POST /@<handle>/net/inbox` with the spine's checks and codes in order (415, 413, 400 bad_request, 400 wrong_recipient, 400 stale, 429 from the Rate Limiting bindings `INBOX_IP_LIMIT`/`INBOX_SENDER_LIMIT`, namespace ids 10601/10602, the sender limit keyed per sender and tau; 404 for a handle without an account after those; then in the object: 502 sender_card_unavailable with a 1 h card cache, 403 bad_signature, 200 duplicate, 429 at 60/h per sender, 503 mailbox_full at 1 000 queued). Accepted envelopes answer **202** `{"status": "accepted", "id"}`, not 200: tau-net counts only 202 or a duplicate as delivered. They wait in `net_queue` and are handled right after with `ctx.waitUntil`; a stuck one is retried by the alarm, at most 3 tries.
  - **Behaviour** (src/net/node.ts) is tau-net's: contacts state machine with key pinning, strangers and blocked senders dropped before anything is fetched, network turns with tau-net's frames word for word (src/net/frames.ts), the persona + public note (`net_note`; a public sub-tau without its own note uses it, now also for `/api/visit`), `## Now` with "not shared with other taus", no tools, `[no reply]` incl. a trailing one, 6 hops, 20 auto-replies per contact and hour, `net_auto_reply` switch, deterministic reply ids, `sub` by hops parity, log capped at 500, counts per contact. Differences from a hub: one model call per turn (the frame's history is the conversation, no per-contact session), constants for max_hops and the hourly cap, no `universe_links` switch.
  - **Visits:** handled, not dropped: a `visit` from the universe this tau joined (`UNIVERSE`), keys pinned at the first visit, public + web sub-tau within `web_daily` (the same counter as `/api/visit`), answer to the universe. Reason: an own host listed in another universe (tau.getporti.com without a HOST binding to it) is reached only by `visit` envelopes; on tau.getporti.com the universe uses `/api/visit` instead.
  - **Sending:** `net_send(address, text)` (tau-net's argument names) is tier 2 in the chat with the existing approval card; `net_contacts` and `net_log` are tier 0. App actions that speak for the owner, adding a contact and sending a message, create an approval card without a session (`session = ''`) that `POST /api/host/approvals/<id>` runs or refuses (NDJSON: start, tool_result, done); accept/decline/block/remove are direct. Another hosted tau on the same host is reached through the Worker's own handler (src/net/transport.ts), without a subrequest; requests to the universe go through the optional service binding `UNIVERSE_SERVICE` when bound.
  - **Universe:** `UNIVERSE` var (left out = the net host itself; `""` = off; `configure --universe HOST|off`), `UNIVERSE_SERVICE` binding (`configure --universe-service tau-universe`). The onboarding choice (never preselected) and a settings PATCH schedule the join 30 s later via the alarm; the app's toggle `POST /api/host/net/universe {join}` joins and reports (or leaves) at once. Reports hourly from the alarm while wanted: snapshot first, accepted listed contacts with in + out counts, public sub-taus `{name, about, web, starters}` ≤ 20; `not_joined` → join again; `stale` retried 3× with the next `ts` (kept per tau); leave forgets the pinned universe keys; a deleted account leaves first; failures are the listing's status, retried hourly.
