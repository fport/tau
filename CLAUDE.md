# tau

Personal "smart body" agent platform. A Strands agent runs on the **hub** (MacBook now, RPi5 later), talks to the user through Telegram, a TUI, the TauBar tray app and voice, reaches devices through **nodes** (MCP for capabilities, Zenoh for events), keeps its state on the hub (local mode, default) or in the owner's own Cloudflare account (cloud mode), and talks to other taus over the **tau network** through its spine Worker.

Read before non-trivial work:

- `docs/ARCHITECTURE.md` — every decision, the principles and the layer roadmap
- `CONTEXT.md` — glossary; use its terms exactly
- `roadmap/README.md` — how issues are tracked and worked
- `docs/adr/0006-private-first-topology.md` — the threat model and the private-first rules every new channel, store or deployment step must respect
- `docs/adr/0007-cloud-mode-and-tau-network.md` + `docs/reference/tau-network.md` — the opt-in cloud mode and the protocol taus use to talk to each other

## Language

- Talk to the user in Turkish.
- Everything in the repo is English: code, identifiers, comments, docstrings, docs, READMEs, ADRs, issues, commit messages, `docs/ARCHITECTURE.md`, `infra/remote/` and the messages its scripts print.
- tau's persona (`persona/persona.md` body) is Turkish by default and language-adaptive: it answers in whichever language the user writes. Its HTML comments and `user.example.md` are English.
- UI chrome (slash commands, labels, pane titles, key hints, notices, approval dialog, CLI help) goes through the `tau_core.i18n` message table (`t(key, language)`), selected by `[ui] language` in `tau.toml` (`en` default, `tr`), `TAU_LANG`, `tau --lang` or `/lang`. Errors raised before Config exists are plain English.
- Everything the model reads (prompt headings `## User` / `## Now`, dynamic-context labels, gate texts, tool descriptions, test personas) is fixed English.
- Never add Turkish strings to code. A Turkish UI string belongs in the `tr` column of the message table, nowhere else.

## Packages and modularity

This repo is the center. Everything is built so it can be published or split out later.

- Every directory in `packages/` is an independently publishable PyPI distribution named `tau-<name>` with the flat import name `tau_<name>`. Do not use a `tau` namespace package: `tau` is taken on PyPI (as are `tau-hub` and `tau-agent`).
- Each package has its own `pyproject.toml`, version, README and tests, and depends on other packages only through their public API as declared dependencies — no path hacks, no private imports.
- Extension goes through entry points (`tau.tools`, `tau.commands`, `tau.providers`, `tau.sessions`, `tau.context`, `tau.hub_services`; later `tau.nodes`, `tau.channels`). A package developed in another repo plugs in with `pip install`, without changes here. `tau components` lists what is installed.
- Split a package into its own repo when it needs its own release cadence, firmware or contributors; tau then consumes it from PyPI and the entry-point contract stays the same.
- Python 3.12+ with a uv workspace. TypeScript parts (`cloud/`, `apps/taubar`) use pnpm.

## Working on issues

- `python3 roadmap/board.py --next` lists what an agent may pick up. Only take `ready-for-agent` issues whose blockers are `done`.
- Never work `ready-for-human` or `needs-hardware` issues on your own; they need the user.
- Follow the workflow in `roadmap/README.md`: `in-progress` → build → tick acceptance criteria → `done` with a dated note under `## Comments`. Run `python3 roadmap/board.py --check` after editing issue files.
- Unclear spec: set `needs-info`, write the question under `## Comments`, stop. Out-of-scope findings become new `needs-triage` issues.

## Non-negotiables

- **Tiers:** tier-2 actions (physical world, activating self-written tools, speaking for the owner to another tau) always go through approval. Never bypass or auto-approve it, including in tests (use fakes for the approver instead).
- **Robot:** simulation is the default. Never enable real mode or move real hardware unless the user says so in the current session.
- **Reflexes** (routines, safety stops) must work without an LLM and without the cloud.
- **Models:** code asks for a role (`brain`/`fast`/`local`), never a hardcoded model id. Never add `litellm` as a Python dependency — the proxy runs as a digest-pinned container (PyPI compromise, March 2026).
- **Secrets:** never commit them. Local `.env` (gitignored), `wrangler secret` for Cloudflare.
- **Privacy:** the repo may go public, so nothing personal goes into tracked files: no hostnames, tailnet names, IP addresses, emails, account ids or key fingerprints. Use example values (`my-mac.tailXXXXXX.ts.net`, `100.x.y.z`, `SHA256:...`). Real values the user shares go into the gitignored `.env`, with the name and an example value in `.env.example`.
- **State (ADR 0006, 0007):** local mode is the default: life data (sessions, settings, memory, KB, routines) stays under `TAU_DATA_DIR` on the hub; the only cloud copy is a client-side encrypted backup in R2. In local mode no code path puts personal data into D1, KV, Vectorize or AI Search, the spine holds only sealed envelopes in transit, no server sits between an external channel and the hub, and the hub never opens an inbound port. Cloud mode (the hub in a Container, data in the owner's own D1/KV) happens only when the owner deploys the cloud config and runs `tau cloud push`.
- **tau network (ADR 0007):** envelopes are always signed and sealed; the spine never sees plaintext or contacts; a network turn never sees `user.md`, gets no tools and refuses every approval; `net_send` stays tier 2. Everything a peer sends is untrusted text.
- **Remote access:** changing `infra/remote/sshd/tau.conf` must keep password auth off and `AllowUsers` restricted to tailnet + localhost; re-run `infra/remote/doctor.sh`.

## Commits

Conventional Commits in English: `type(scope): summary` — scopes like `remote`, `core`, `tui`, `net`, `mesh`, `robot`, `cloud`, `taubar`, `roadmap`, `docs`. Small, logical commits; reference the issue id in the body (`Refs: 004`).

## Commands

```sh
python3 roadmap/board.py [--next|--human|--check|--layer L1]   # roadmap
infra/remote/doctor.sh                                         # remote access health
infra/remote/setup.sh                                          # re-apply remote access (idempotent)

# Python (uv workspace, Python 3.12; never pip-install into the system python)
uv sync --all-packages --group dev                             # install every package + dev tools
uv run tau init                                                # first config: tau.toml + persona/user.md from templates
uv run tau doctor                                              # config, credentials, session store, persona, .env names, hub API
uv run tau components                                          # every tau.* entry point with distribution, version, state
uv run tau chat                                                # talk to tau in the terminal
uv run tau tui                                                 # Textual UI (#008)
uv run tau --lang tr chat                                      # UI chrome in Turkish for this run (also TAU_LANG, [ui] language)
uv run tau hub run|status|stop|install|uninstall               # hub daemon (#009)
uv run pytest -q                                               # all tests, offline (FakeModel)
uv run ruff check .                                            # lint
uv run ruff format .                                           # format (CI runs --check)
uv build --package tau-core                                    # standalone wheel in dist/
uv run tau net init|status|add|accept|send|log|poll --once     # tau network (#093)
uv run tau cloud push|pull|status                              # cloud mode: persona + tau.toml to the spine (#094)
(cd cloud/spine && pnpm install && pnpm run configure && pnpm dev)   # spine locally on :8787 (#092)
(cd cloud/spine && pnpm test)                                  # spine tests (vitest, workerd)
(cd cloud/spine && pnpm run deploy)                            # deploy the spine (after wrangler login)
uv run --group docs mkdocs serve                               # docs site at http://127.0.0.1:8000
uv run --group docs mkdocs build --strict                      # what CI runs for the docs
```

`tau chat` and `tau tui` share the slash commands `/help /tools /sessions /resume /new /session /lang /quit` (Turkish aliases are accepted, never shown).

Config lives in `tau.toml` (roles → provider + model id, `[ui] language`, `[components]`) and `.env` (credentials; names in `.env.example`). Tests never need credentials: use `tau_core.testing` (`FakeModel`, `ScriptedApprover`, `test_config`). TypeScript commands: `cloud/spine` (#092) and `apps/taubar` (#024).
